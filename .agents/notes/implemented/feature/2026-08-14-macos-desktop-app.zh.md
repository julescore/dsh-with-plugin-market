# Agent Note: 原生 macOS 桌面应用

Status: implemented

[English](2026-08-14-macos-desktop-app.md) | 中文

## 问题

DeepSeek Harness 可以从终端运行并提供 Web 客户端，但 macOS 用户没有可双击启动完整产品的自包含应用。要求用户另外安装 Node.js 工具链并手动执行 Host 命令，会让本地桌面使用依赖开发环境。桌面分发必须保留既有 Host、Web 客户端、profile 数据与凭据归属，而不是把它们分叉为第二套产品实现。

## 决策

**原生 AppKit 外壳负责桌面启动和呈现。** 应用由单个 Swift 源文件编译，创建标准 macOS 窗口，并在 `WKWebView` 中显示既有 Web 客户端。它不会用 Swift 重复实现 Harness 服务或客户端行为。

**应用包持有固定版本的生产运行时。** 构建会内置 Apple Silicon Node.js 24.19.0 可执行文件、已构建的 CLI 与 Web 资源，以及生产依赖闭包；还会将 `dshmarket@1.2.3` 与 `pnpm@11.7.0` 作为仅用于分发的资源内置。三个压缩包都只有在固定 SHA-256 摘要匹配时才会被接受。部署元数据遗漏的工作区包会从同一检出源码中物化，而且必须已经包含构建后的入口文件。

**桌面应用预装插件市场，但不改变 CLI 产品。** 应用自有的 `--patch` 只在 AppKit 启动时挂载 dshmarket。市场把安装请求限制在精选目录内，优先使用经过仓库映射的 npm 包，并保留用户确认；目录收录不代表安全背书。由于 `dsh-web-ui` 仓库根目录不是 profile bundle，macOS 分发会把该 monorepo 映射到作者发布的预构建全家桶 `@linxin666/dsh-web-ui-all`。安装该全家桶前，如果用户尚未作出选择，市场会把 `cloudflared`、`cpu-features` 和 `ssh2` 的构建脚本记录为 `false`，从而避免下载二进制文件与编译原生扩展，且不扩大任何权限。既有选择与其他目录条目保持不变。内置 pnpm 使插件管理不依赖用户的 shell 配置。市场与包管理器的许可证声明随运行时一同分发。

**已有本地市场时必须明确选择来源。** 启动 Host 前，外壳会导出 Web 最终组合，并检查其顶层行中是否存在 `dsh-market`。冲突提示框提供本地市场、安装包市场和退出。选择本地时不应用桌面市场补丁；选择安装包时，只在当前进程组合中禁用本地行，并通过 `dshmarket-bundled` 别名插入安装包代码。组装过程会同时改写该别名的包元数据和客户端注册 ID。选择不会持久化，两条分支都不会编辑或删除本地 profile 数据。

**既有 Web Host 继续作为应用边界。** 外壳根据当前市场状态选择补丁并执行 `dsh web --port 0`，Web 视图只接受就绪信息中报告的 `127.0.0.1` 来源，并把外部 HTTP 或 HTTPS 导航交给系统浏览器。随机回环端口避免固定端口冲突，也不会在局域网接口上暴露 Host。

**桌面使用保留正常的用户数据位置。** Host 从用户主目录启动并使用 `~/.dsh`。设置、会话和凭据引用不会被复制进应用包，也不会由应用包迁移。

**外壳负责 Host 生命周期。** 应用终止时先向子进程发送 `SIGTERM`，六秒后仍未退出则升级为 `SIGKILL`。启动失败或子进程意外退出时，加载界面会替换为错误信息，而不是留下无响应的 Web 视图。

**社区发行版使用独立产品标识。** 应用、DMG、仓库与 Release 产物统一使用 `DSH with Plugin Market`，bundle identifier 为 `io.github.julescore.dsh-with-plugin-market`。上游 `@deepseek-ai/*` 包名与产品内部组合保持不变，使官方源码更新仍可合并。

**GitHub 自动化负责构建发行版并提出上游同步。** 桌面工作流在原生 runner 上构建并验证 macOS arm64 产物，只有版本匹配的 `desktop-v*` 标签才会发布 Release。每周同步工作流会将官方 `deepseek-ai/deepseek-harness` 的 `master` 合并到专用分支并创建 PR，绝不直接把上游更新写入发行分支。

**仓库构建生成本地安装产物。** `pnpm run build:macos` 在 `.artifacts/macos` 下创建 arm64 `.app` 和带版本号的压缩 DMG，并应用和验证 ad-hoc 签名。Developer ID 签名与 Apple 公证仍属于外部发布操作，因为仓库不持有分发凭据。

**应用拥有独立的发布版本。** `apps/macos/version.json` 是发布版本与单调递增 Apple 构建号的唯一来源；根工作区包版本不控制桌面应用发布。RC 后缀保留在 DMG 名称中，`CFBundleShortVersionString` 使用稳定的三段版本，`CFBundleVersion` 使用整数构建号。

**正式打包以事务方式提升并验证版本。** `pnpm run package:macos` 默认提升候选版本，再构建应用，并使用隔离的临时 `DSH_HOME` 验证挂载后的 DMG。流程也支持明确指定稳定发布、语义化版本和目标版本。只有全部步骤成功后才保留新 manifest；失败时恢复此前的文件字节并删除不完整产物，同时保留旧版本 DMG。

## 曾考虑的替代方案

**使用 Electron 或其他内置浏览器运行时。** 不采用：产品已有 Web 客户端，而 macOS 自带 WebKit。AppKit 加 `WKWebView` 显著减少运行时与打包范围，同时保留既有客户端。

**在默认浏览器中打开 Web 客户端。** 不采用：这不会提供应用窗口或桌面生命周期归属，而且用户关闭界面后 Host 进程仍会脱离该界面继续存在。

**用原生 Swift 重写客户端或 Host。** 不采用：这会形成插件组合、会话行为、设置与客户端体验的第二套实现，而不是分发已组装的产品。

**依赖系统安装的 Node.js 或 pnpm。** 不采用：双击启动和市场安装都不应依赖 shell 配置或兼容的开发工具链。固定内置工具也明确了它们的版本。

**把市场加入内置 Web profile。** 不采用：这会改变每一次 CLI 与 Web 启动。桌面专用覆盖层把用户要求的分发行为限制在 DMG 内。

**使用固定本地端口。** 不采用：同时运行开发实例或多个应用实例时可能发生冲突。Host 已支持选择可用端口并报告就绪 URL。

**使用根包版本发布桌面应用。** 不采用：工作区与桌面产物的发布节奏不同，绑定两者会产生无关的工作区版本变更。

**在脚本与 `Info.plist` 中重复维护版本。** 不采用：多个可编辑副本会发生漂移。构建会从同一个已验证 manifest 注入两个 Apple 版本字段和 DMG 名称。

**打包失败时仍然提升版本。** 不采用：未交付的尝试不应消耗发布标识或构建号。打包命令只有在构建与验证全部完成后才会保留 manifest 改动。

## 验证契约

应用包必须通过严格的深度签名验证，不存在损坏的符号链接，并且任何 arm64 Mach-O 的加载命令都不得要求高于 plist 声明的 macOS 版本。从挂载的 DMG 启动时，应用必须创建可见的零层级窗口，启动只监听 `127.0.0.1` 的子 Host，公开市场 Host 路由与 Web 客户端，并在应用终止后释放子进程及其端口。在 `PATH` 中只提供内置包管理器的条件下，验证必须通过当前目录的子目录 URL 安装 `dsh-web-ui`，证明 npm 全家桶成为 profile layer，检查三项明确的构建脚本拒绝策略，重启 Host 后在 Web 启动图中找到全部七个全家桶客户端，再卸载该全家桶。旧市场夹具还必须证明第一次更新请求能跳过发布时间等待，将 `dshmarket@1.1.0` 升级到 1.2.3。隔离的全新与冲突主目录必须证明全新、本地选择和安装包选择三种启动都只激活一个市场客户端，而且两种冲突选择都保持 profile manifest 不变。打包验证不得接触用户凭据存储，并保持已安装应用的现有进程继续运行。文档门禁保持中英文参考文档和本决策记录成对一致。

## 后果

macOS Apple Silicon 用户无需安装 Node.js 或 pnpm，即可安装 DMG、启动同一套 Harness Web 产品并管理精选插件。应用继续与 CLI 共享 profile 和凭据，因此桌面与终端使用并不隔离。从桌面市场安装的插件也会改变共享的 Web profile。由于携带 Node.js、pnpm、dshmarket 和完整生产依赖图，应用包体积更大。它要求 macOS 15.0 或更高版本，因为这是内置 arm64 原生依赖集合编码的最高最低版本。正式打包成功后会提升应用构建号并保留旧版本 DMG，而普通重建保持当前版本。ad-hoc 签名适合本地交付和验证，但不适合无阻碍的公开下载；面向外部用户的发布仍需要 Apple 签名与公证。在构建加入 x64 运行时与可执行文件或生成通用应用之前，Intel Mac 不受支持。
